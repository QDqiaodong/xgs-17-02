# 园区公共饮水机管理系统

## 项目简介

园区后勤饮水机管理系统，按园区、楼栋、楼层三级树形分组维护设备档案、分组调整和变更记录；
并提供「饮水机水质抽检与复检」闭环模块：按区域发起抽检批次、阈值自动判定、草稿/待复核/退回/待复检/已关闭全状态流转、不合格项复检链路、历史快照与并发防重。

设备档案首页为「全园设备快速检索」，支撑十万级设备的组合筛选与稳定翻页（详见下文）。

## 全园设备快速检索

- 七维组合筛选：区域树范围（选中园区/楼栋自动包含**全部下级**区域）、设备编号（前缀）、型号、安装规格、出水类型、启用状态、待复检标记，可任意叠加。
- 结果每行直接由数据库三级 JOIN 产出**完整区域路径**（园区 / 楼栋 / 楼层），**不逐行查树**；区域树用祖先-后代**闭包表** `building_group_closure` 维护，选节点一次查询得到全部下级，应用启动幂等回填。
- **游标键集分页（keyset pagination）**：排序永远是 `(主排序值, 设备id)` 二元键，id 唯一决胜，即使大量设备主排序值相同也不会页间抖动；连续向后翻页不重复、不跳过，深翻页性能与页码无关。支持建档时间/设备编号/型号/安装日期四种排序与升降序。
- 游标为 HMAC 签名的无状态令牌（默认 30 分钟有效，密钥见 `DEVICE_CURSOR_KEY`），内含筛选条件指纹：篡改即拒绝、过期明确返回 410、更换任一筛选/排序/页大小旧游标立即失效并从新结果起点开始。
- 筛选条件、排序、页大小、当前页位置全部在浏览器地址（hash query）中：刷新、前进/后退、复制地址给同事都能恢复同一视图；游标过期时保留筛选条件并提示从第一页重新检索。详情为弹窗，关闭后筛选条件、页码与滚动位置原样保留。
- 缓存：首页与筛选项走 Redis 短缓存（30 秒 / 5 分钟），Redis 任何故障自动降级直查数据库；缓存内容是 DB 结果的原样 JSON，恢复后同一查询的过滤规则、字段格式与排序不因来源不同而变化。
- 接口：`GET /api/water-dispenser/search`（游标分页）与 `/api/water-dispenser/search/facets`（型号/规格/出水类型可选项）。旧的 `/water-dispenser/page` 保留供抽检批次选择设备使用。页大小服务端钳制在 200，杜绝一次性读入全表。
- 验收：`DeviceSearchIntegrationTest`（H2 MySQL 模式）构造 **10 万台设备 / 24 个楼层**，全量翻页核对无重复无跳过、与数据库确定序逐行一致；每页固定 1 条检索 SQL、区域解析 ≤1 条闭包 SQL；覆盖组合筛选、游标过期/篡改/串用、缓存宕机降级与恢复一致性。运行：`cd backend && mvn test`。

## 水质抽检与复检模块

- 按园区/楼栋/楼层发起批次，从设备档案选择饮水机，记录采样时间、采样人、余氯、浊度、温度、气味结论和现场照片。
- 提交时按后台生效阈值自动逐指标判定，并把阈值 JSON 固化到批次；后续改阈值不影响已提交批次（含复检）。
- 一台不合格即进入待复核，并把对应设备标记为「待复检」；该标记与设备启用/停用状态正交，不覆盖停用状态。
- 采样记录保存提交当时的设备编号、型号、完整区域路径快照；设备调组/改名后历史仍显示原采样位置，详情同时对照当前区域。
- 状态机：草稿（可增删设备/改结果）→ 提交后原始数据不可直改 → 待复核 →（整批退回 | 待复检）→ 已关闭。
- 复核人不能复核本人提交；可整批退回填原因，或确认合格项、为不合格设备逐指标开启复检。
- 复检关联原不合格项并保留历次结果；同一设备全部未关闭不合格项复检合格才解除「待复检」；停用设备只关闭问题不自动启用。
- 并发防重：批次/不合格项行锁 + 批次乐观锁版本号 + 客户端幂等键（requestId），重复点击/网络重试不会产生重复复检记录、状态变更或照片引用；冲突返回 409，前端提示并刷新到最新状态。
- 提交/复核/复检均为单事务，任一设备、状态历史或照片关系写入失败则整体回滚。
- 列表支持区域、批次状态、采样日期、设备编号筛选；详情含原始采样、复核意见、复检链路、每次状态流水。
- 后端包含 13 个集成测试（H2 MySQL 模式）覆盖上述闭环与并发场景：`cd backend && mvn test`。


## 技术栈

- 前端：Vue 3、Vite 5、Element Plus、Pinia、Axios、Compressor.js
- 后端：Spring Boot 3、JDK 17、MyBatis-Plus、Spring Data Redis、Maven
- 数据：MySQL 8、Redis 7
- 部署：Docker Compose、Nginx

## 端口说明

| 服务 | 地址 |
| --- | --- |
| 前端 | http://localhost:3217 或 http://127.0.0.1:3217 |
| 后端 API | http://127.0.0.1:8217/api |
| MySQL | 127.0.0.1:3517 |
| Redis | 127.0.0.1:6517 |

端口来自根目录 `.env`，Docker 端口只绑定 `127.0.0.1`。

## 启动方式

```bash
cd xgs-17
docker compose up -d --build
```

本地拆分验证：

```bash
cd backend
mvn compile -q

cd ../frontend
npm ci
npm run build
```

## Docker 构建说明

Docker Compose 统一构建后端 Spring Boot 镜像、前端 Nginx 镜像，并启动 MySQL、Redis：

```bash
docker compose up -d --build
docker compose ps
```

## 常见问题

- 后端编译失败：检查 JDK 17、Maven 依赖和 Lombok/annotation processor 配置。
- 前端构建失败：按 Vite、import 路径、组件导出或语法错误定位。
- 页面运行时接口失败：build 通过后检查 backend、数据库、Redis 和 `/api` 代理。
